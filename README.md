## 3. Откройте и запустите блокнот

`.ipynb` — файл Jupyter Notebook. Он состоит из текстовых ячеек Markdown и ячеек с Python. GitHub умеет показывать такой файл, но не выполняет код на странице репозитория.

### Подготовленный Jupyter на компьютере

Откройте терминал в своей папке решения. Если Jupyter уже установлен, выполните:

```bash
jupyter notebook
```

В браузере откройте свой файл и выберите ядро Python 3. В учебном окружении используем Python 3.12. Текстовые ячейки читайте, кодовые редактируйте. `Shift+Enter` выполняет текущую ячейку и переводит к следующей. `Ctrl+S` сохраняет блокнот. Можно выполнить все кодовые ячейки через команду **Run All** или **Restart Kernel and Run All Cells** своей среды.

Каждая задача самостоятельна: ей не нужны переменные, созданные в соседних ячейках. В блокноте ровно десять кодовых ячеек. Не создавайте установочные или дополнительные ячейки.

### Google Colab без локальной установки

Если подготовленного Jupyter нет, можно открыть [Google Colab](https://colab.research.google.com), загрузить свой `.ipynb` через меню открытия файла и вкладку загрузки. Выполняйте ячейки в среде Python 3. Этот способ требует интернета и аккаунта Google, но не установки библиотек на компьютер.

После работы скачайте **именно `.ipynb`**, а не `.py` или PDF, через меню скачивания блокнота. Замените им файл в своей папке решения. Откройте скачанную копию и убедитесь, что в ней сохранились решения и выводы десяти ячеек.

### Запуск обычным Python без Jupyter

В исходном задании есть `run_notebook.py`: он читает кодовые ячейки стандартными средствами Python, выполняет каждую отдельно и может сохранить выводы в `.ipynb`. Это способ запуска уже отредактированных ячеек; для удобного редактирования используйте среду, поддерживающую блокноты.

Из папки распакованного задания выполните, подставив путь к своему файлу:

Windows PowerShell или cmd:

```powershell
py -3.12 run_notebook.py "C:\путь\к\my-python-solution\07.ipynb" --save
```

Если команды `py` нет, проверьте `python --version` и используйте `python run_notebook.py ...` с тем же путем. Кавычки нужны, если в пути есть пробелы.

macOS / Linux:

```bash
python3 run_notebook.py "/путь/к/my-python-solution/07.ipynb" --save
```

Замените `07.ipynb` своим именем файла. Ключ `--save` сохраняет выводы и номера выполнения в блокноте. Без него результат виден только в терминале. Если ошибки остаются, они также будут записаны в вывод соответствующих ячеек. Исправьте код и повторите запуск. Устанавливать библиотеки для этой команды не нужно.

## 4. Как выполнять задачи

Для каждой задачи:

1. Прочитайте условие: какие данные заданы, что получить, в какие переменные записать результат и какого он должен быть типа.
2. Изучите теорию и пример. Пример показывает приём на других данных; его нельзя просто скопировать как ответ на свой вариант.
3. Найдите в единственной кодовой ячейке границы:

```python
# >>> РЕШЕНИЕ
# TODO: здесь нужно написать решение
# <<< РЕШЕНИЕ
```

4. Меняйте только строки между границами. Заменяйте `...` рабочими выражениями; если уже дан пустой список или словарь, дополните его алгоритмом.
5. Используйте переменные исходных данных. Не подставляйте заранее вычисленные числа или готовые списки вместо алгоритма.
6. Выполните всю ячейку. Если появляется ошибка, исправьте решение и запустите ту же ячейку снова.
7. После правильного результата сохраните выданный фрагмент и переходите к следующей задаче.

Не меняйте исходные данные над блоком, имена требуемых результатов, границы блока и проверку внизу. Текстовые условия и порядок ячеек оставляйте на своих местах. Служебные импорты уже присутствуют в проверке; в свои решения добавлять импорты, ввод с клавиатуры, чтение файлов или обращения к интернету не нужно.

### Какие приёмы требуются

| № | Приём |
|---|---|
| 1 | Целочисленное деление `//` и остаток `%` |
| 2 | Методы строк `strip`, `lower`, `replace` |
| 3 | Ветвление `if / elif / else` и сравнение с границами |
| 4 | Список, цикл `for`, условие и `append` |
| 5 | Распаковка кортежа и создание нового кортежа |
| 6 | Множества и операции `&`, `-`, `|` |
| 7 | Словарь и подсчёт повторений циклом `for` |
| 8 | Функция с параметрами, значением по умолчанию и `return` |
| 9 | `sorted` с `lambda` непосредственно в `key=` |
| 10 | Списковое включение с условием и форматирование строк |

### Как читать сообщения об ошибках

| Сообщение | Что проверить |
|---|---|
| `SyntaxError` | Двоеточия после `if`, `for`, `def`; кавычки и скобки |
| `IndentationError` | Отступы: четыре пробела внутри блока, без смешивания табуляции и пробелов |
| `NameError` | Точное написание имён переменных из условия |
| `TypeError` | Тип данных: число, строка, список, кортеж, множество или словарь |
| `AssertionError` | Вычисления, границы условия, порядок элементов, требуемый тип и оставленные `...` |
| Фрагмент не появляется | В ячейке остаётся ошибка или результат не соответствует условию |

Одинаково выглядящие значения могут иметь разные типы: например, `(1, 2)` — кортеж, `[1, 2]` — список. Проверяется и содержимое, и тип. Для множеств и словарей порядок элементов при сравнении не важен; для списков, кортежей и строк — важен.

Проверка преподавателя использует дополнительные исходные данные и проверяет указанные конструкции. Наличие напечатанной фразы само по себе не заменяет правильный код. Проверку и фрагменты в ячейках редактировать нельзя.

Перед сдачей перезапустите ядро и выполните все ячейки заново либо воспользуйтесь `run_notebook.py ... --save`. Убедитесь, что все десять задач выполняются без ошибок. Сохраните файл с выводами. Проверяйте именно тот `.ipynb`, который будете загружать в GitHub.

## 7. Загрузите решение в GitHub

### Создайте удалённый репозиторий

1. Войдите в свой аккаунт [GitHub](https://github.com).
2. Нажмите **+ → New repository** и задайте имя, например `python-basics-solution`.
3. Выберите видимость согласно требованиям преподавателя. Для закрытого репозитория предоставьте ему доступ.
4. Оставьте репозиторий пустым: не добавляйте через форму README, `.gitignore` и лицензию, поскольку локальные файлы уже готовы.
5. Нажмите **Create repository** и скопируйте HTTPS-адрес своего репозитория.

### Создайте локальную историю Git

Установленный Git проверьте командой `git --version`. Откройте терминал **в отдельной папке своего решения**, где находятся README и один блокнот. Для перехода используйте `cd "ПУТЬ_К_ПАПКЕ"`; в Windows cmd для перехода на другой диск — `cd /d "ПУТЬ_К_ПАПКЕ"`.

```bash
git init
git branch -M main
```

Если Git просит имя и почту автора, настройте их для этой папки:

```bash
git config user.name "Имя Фамилия"
git config user.email "ВАША_ПОЧТА"
```

Используйте свою почту либо свой адрес `noreply` из **GitHub → Settings → Emails**.

Добавьте только файлы решения, заменив `07.ipynb` своим именем:

```bash
git add .gitignore README.md 07.ipynb
git diff --cached --name-only
```

В выводе должны быть ровно эти три файла и только один `.ipynb`. Если случайно добавили чужой блокнот, до первого коммита уберите его из индекса через `git rm --cached ИМЯ_ЛИШНЕГО_ФАЙЛА`. С `--cached` файл остаётся на диске. Повторите проверку списка.

Сделайте коммит, подключите адрес своего пустого репозитория и отправьте файлы:

```bash
git commit -m "Complete Python notebook"
git remote add origin https://github.com/USERNAME/python-basics-solution.git
git push -u origin main
```

Замените `USERNAME` и имя репозитория на свои. При первом `push` может открыться авторизация в браузере. Завершите вход своим аккаунтом. Обычный пароль GitHub не используется как пароль Git по HTTPS; при запросе токена воспользуйтесь настроенным менеджером учётных данных или официальной инструкцией по авторизации.

`git add` подготавливает файлы, `git commit` сохраняет их локально, а `git push` загружает коммиты в GitHub. Одного локального коммита для сдачи недостаточно.

### Проверьте опубликованные файлы

Откройте страницу своего репозитория и убедитесь, что:

- загружен ваш блокнот из правильной группы;
- внутри есть десять решений и выводы десяти ячеек без ошибок;
- в README указаны автор, группа, вариант и точный афоризм;
- нет других блокнотов и папки `tasks` со всеми вариантами;
- преподаватель может открыть репозиторий.

Для исправлений после публикации:

```bash
git add README.md 07.ipynb
git commit -m "Update notebook solution"
git push
```

Замените имя блокнота своим. Если `origin already exists`, проверьте `git remote -v` и в своей папке решения исправьте адрес через `git remote set-url origin ВАШ_HTTPS_АДРЕС`. Если новый удалённый репозиторий оказался непустым, можно создать другой пустой и заменить адрес; не перезаписывайте чужую историю принудительной отправкой.

Передайте преподавателю ссылку вида `https://github.com/USERNAME/python-basics-solution`. Сам блокнот дополнительно прикреплять не требуется, если он уже находится в вашем репозитории.
